# Website maintenance

For website work, start with [docs/development.md](docs/development.md) and the local design
specification it links. Reuse the existing Astro source, token system, tests,
and Pages deployment. Preserve publication facts, source provenance, paper
assets and localized content; do not reinterpret example commands or model
results. Inspect the current branch and open PRs, validate the changed layer,
and report exact candidate and actual serving state separately.

For material page/feature changes, resolve the relevant [Feature Design](docs/design/features/README.md) (intent and realization), preserve source-backed essential outcomes, then actively compare and verify a better feasible design using the latest owner intent, technology and evidence. Do not freeze the old implementation or infer approval from a passing test.
